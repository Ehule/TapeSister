# F11 cockpit validation

This is the first implementation stage: the control-center overview, local
Mosaic cues, input/tuner and visualizer pages. Master-clock routing and persistent
loop cards are separate later stages. Playback DSP and existing transport
semantics are unchanged.

## Development-host checks

Release build on a shared Linux x86-64 development host reporting an AMD EPYC
9V74. SDL dummy video/audio, software renderer, 960x640 logical window. These are
not measurements from the user's X220/X230, HP A8 or 1280x1024 physical display.

- The 15-test PR baseline passes, including save/state, native tracker, Mosaic
  pattern playback/lookup, routing/Matrix and the dedicated F11 test.
- Native controller tests exercise group versus independent transport, actual
  playback row with the editor detached, repeated Pause, explicit rewind, trim
  on custom outputs, score mute versus live solo, local cue seek, cue-loop release,
  a cue endpoint beyond the arrangement, and logical/window-coordinate mapping.
- Input tests exercise 26-channel paging, raw pre-trim tuning with a synthetic A3
  seven cents sharp, six-channel monitoring through the real output callback,
  F9 raw-route independence, page suspension and close with monitor feeds retained.
- The cockpit does not consume source-route meter activity. Native screenshots
  are generated by the integration fixture, not reconstructed product mockups.

Explicit UI benchmark: `TS_COCKPIT_BENCHMARK=1
tapesister_source_route_controller_tests --cockpit <screenshot-directory>`.
One run, 100 forced paints per case:

| Sample cards | Metadata policy | Mean paint time |
| ---: | --- | ---: |
| 1 | Ordinary four-Hz cache | 1.086 ms |
| 1 | Force refresh every paint | 1.427 ms |
| 1024 | Ordinary four-Hz cache | 1.115 ms |
| 1024 | Force refresh every paint | 1.070 ms |

Shared-host scheduling noise exceeds the metadata difference in this short run.
These are UI sample-card metadata measurements, not dense pattern-audio
benchmarks, callback deadlines, hardware display costs or a speedup claim. At the
normal twenty-Hz ceiling the measured paint work is roughly 22-29 ms per second
on this host. Hidden/minimized windows do not paint; no callback DSP is added.

## Practical hardware check

1. Open a copy of a familiar project. Note F12's buffer/rate and recent load.
   Play it with F11 closed, then open Overview. Compare recent load and observed
   overruns with the same buffer settings; retain the Audio Health log if a new
   problem appears. A counter increase alone is not proof of an audible dropout.
2. Uncheck TrackSister while it is playing. Pause Group: the unchecked player
   should continue. Check mute/solo and zero-trim states separately from Playing.
   Test held QWERTY/MIDI notes and edit during playback.
3. Trigger Mosaic cues, enable cue looping and release it mid-range. Mosaic
   should continue forward on release, while the other players keep position.
   Try overlapping sample/pattern cards and a direct Matrix route; F9 meters
   should still work with F11 open.
4. Check only intended live inputs. Visit another page, close/reopen F11, and
   verify those monitor feeds continue. Tuning suspends outside Inputs/Tuner;
   closing F11 switches the tuner off. Check F9/F12 and Offline Render access.
5. Inspect the 960x640 window on the 1280x1024 monitor and laptop screen, including
   OS title/task bars. Try Alt+F11, theme changes and Tab/Shift+Tab page navigation.

The MAIN meter is scoped to its existing tap. Direct outputs and processor tails
can be active when a player is stopped or MAIN is quiet. Current scheduled
pattern cards still obey Mosaic transport; the planned persistent looper will
have independent per-card clock, transport and position routes.
